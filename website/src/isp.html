BOUNDARIES THAT PROTECT THE PRODUCT

Good questions
deserve clear answers.

Is this part of the Windows Desktop app?

No. Desktop remains the local-first single-site hotspot manager. ISP Network is a separate premium service for multi-site ISP billing and network adapters. Desktop only provides the entry point and does not become a MikroTik or Omada controller.

Will the first release support MikroTik and Omada?

Those are the first adapter lanes. MikroTik is modeled around RouterOS HotSpot and RADIUS. Omada is modeled around the external portal and controller authorization flow. Each controller or RouterOS version still needs an explicit compatibility test before it is marked supported.

Can I use another access point?

The product can support another vendor only when its captive portal, RADIUS, controller API, session termination, accounting, and recovery behavior are validated. The workspace shows unvalidated vendors as planned instead of pretending they are live.

Where will customer and payment data live?

In the authenticated ISP service, with tenant isolation, encrypted provider credentials, idempotent payment callbacks, audit history, and role-based access. It will not be stored in the Desktop app’s local data folder or in this public static page.
